# Roadmap

[x] done, [ ] not started. Each milestone is a vertical slice that ends with something usable; "Done when" is the exit check.
Agreed on 2026-10-18: Windows desktop and web first; the first usable version is a Jellyfin client (browse + play); anyone may use the
app, so services are optional and features removable (ADR 0008). Reorder later milestones as priorities change.

## Principles
- Anyone may use Current against their own servers. Every service (Jellyfin, Seerr, Stash) is optional at runtime, and features that
  must be removable (adult content first) are extensions that a build can leave out (ADR 0008).
- All logic is shared Kotlin; SwiftUI and Compose only render state (ADR 0005, 0006). Playback UI is always our own (ADR 0007).
- Check API facts against the server's own spec before coding (docs/platform-notes.md). The repo is public: no hostnames, keys or
  private server details in code, docs or commits.

## M1: Foundations and Jellyfin sign-in (Windows desktop, web)
Spikes first: they decide whether the first slice works at all. Each ends in an ADR or a docs/platform-notes.md entry.
Compose Multiplatform has no supported way to draw Compose over native video on either platform, so every candidate is a workaround
(details and sources: docs/platform-notes.md).
- [x] Desktop video (2026-10-19, ADR 0010): libmpv in a native child window with a transparent Compose controls window and our own
      borderless fullscreen. The texture route works but is SDR only; vlcj not tried. Needs our own LGPL-2.1 libmpv/FFmpeg build (with
      Windows media controls)
- [x] Web UI (2026-10-19, ADR 0011): React + TypeScript (Vite) over the Kotlin core compiled to Kotlin/JS, chosen over Compose HTML and
      Compose for web after three prototypes and the owner's hand checks. Web playback is `<video>` + hls.js with a device profile built
      only from browser probes (direct play, server remux, server transcode); HDR10 HEVC plays in HDR on Chrome and Edge
- [x] Dependency licences: permissive and LGPL-2.1 only, no GPL in distributed builds; Store, Full and Personal editions (ADR 0009)
- [x] Current's own code is proprietary: no open-source licence, no LICENSE file (ADR 0009)
- [x] Supported server versions: the latest releases only (Jellyfin 12.2 and Seerr 3.5.0 on 2026-10-18); follow new releases rather than
      keeping older ones working

Then:
- [x] Libraries per ADR 0002, versions checked against Kotlin/CMP: Ktor client, kotlinx.serialization, Koin, Navigation, Coil 3
      (2026-10-19; Navigation is 2.10.0-rc01, the line CMP 1.12.1 pairs with)
- [ ] Extension points, capabilities state and the build switch (ADR 0008); CI builds a shell without extensions
- [ ] `core:model`: media identity (service + id), open media kinds, artwork with aspect ratio, user and permissions
- [ ] `core:network`: client factory per service, error model, lenient JSON, log redaction of tokens, keys and cookies
- [ ] Server setup: add a server by URL, check it (public info endpoint), warn about plain HTTP
- [ ] Jellyfin sign-in with username and password or Quick Connect, one random device id per install (signing in again with the same id
      revokes the old token), sign out; token in secure storage (desktop: OS credential store; web: browser storage, documented risk)
- [ ] Compose shell (desktop): theme from design tokens, navigation assembled from registered destinations, sidebar layout,
      settings (servers, sign out, about), loading/error/empty states, strings in resources
- [ ] Web shell (ADR 0011):
  - [x] pure-Kotlin modules gain a `js()` target (they lose `wasmJs`, and the Compose modules leave the web);
  - [x] a Kotlin/JS umbrella module (`web`) with the `@JsExport` facade;
  - [x] the browser probes and web device profile in `core:playback`, tested against `docs/web-probes/`, with Dolby Vision probes;
  - [ ] `webApp` becomes the Vite + React + TypeScript app, with the same sidebar layout, settings and states as desktop (the app,
        a placeholder home and a playback support page are done; the layout waits for the Compose shell);
  - [x] routing through the core's History API router; npm in CI with a licence check
- [ ] Opt-in live smoke tests (read-only) that run only when test-server environment variables are set; never in CI

Done when: sign in and out of Jellyfin on Windows and in the browser, the app restarts signed in, and a build without extensions passes CI.

## M2: First usable version: Jellyfin browse and play (Windows desktop, web)
- [ ] `data:jellyfin`: libraries, items (paging, sort, filter), latest, resume, next up, series/seasons/episodes, details, similar,
      search, images (+ blurhash), played/unplayed, favorites
- [ ] Home: Continue Watching, Next Up, Latest per library; users can reorder, hide and add sections
- [ ] Library grids, detail screens (movie, series, season, episode), search; home videos, playlists, collections, extras (behind the
      scenes, deleted scenes, interviews), multiple versions and parts; directors and other crew shown and searchable
- [ ] `core:playback`: `PlayerEngine`, `EngineCapabilities`, `PlaybackPlanner` (Jellyfin playback info + device profile from the
      engine's capabilities: direct play, direct stream, remux or HLS transcode)
- [ ] `feature:player`: `PlayerController` (resume, progress reporting with pings while paused, audio/subtitle tracks, quality limit,
      next episode, skip intro/credits where the server has a media-segment plugin, fall back to transcode on engine errors)
- [ ] Engines: desktop (from the spike, ADR 0010: our LGPL-2.1 libmpv/FFmpeg build, JVM binding, window host and its follow-ups),
      web (HTML video + hls.js)
- [ ] Player UI in Compose (desktop) and React (web): transport, seek bar with chapters, track and quality menus, fullscreen, keyboard
      shortcuts, auto-hide
- [ ] Web player follow-ups (ADR 0011):
  - ask for a new route when the display's dynamic range changes;
  - check HDR on screen by eye;
  - render ASS in the browser instead of burning it in (a JavaScript renderer; check its licence first)
- [ ] Media keys: Windows (System Media Transport Controls, in our libmpv build per ADR 0010), Media Session API on web
- [ ] The rest of the player feature target (ADR 0007) as far as Windows and web allow: HDR output, subtitle appearance, delay and preferred
      languages, remembered quality and zoom, a playback info overlay, a problem report with redacted logs
- [ ] Deploy the web build (static files) behind a reverse proxy for daily use

Done when: a Jellyfin library is browsable and playable on Windows and web every day, with resume and progress synced to the server.

## M3: Seerr: discover and request
- [ ] Seerr sign-in without storing a password: Seerr's Jellyfin Quick Connect, with the code approved by the app's own Jellyfin session,
      also to renew the 30-day session silently; password or local account as fallback
- [ ] Web: Seerr has no CORS, so serve the web app on the same origin as Seerr's API (reverse proxy) or add CORS to Seerr (server change); decide
- [ ] Discover rows as the server configures them, Movies/Series browse with filters, search merged with library results
- [ ] Movie, series, person and collection pages joined with Jellyfin through Seerr's media records first, provider ids second (often missing)
- [ ] Requests: request (seasons, 4K, advanced options when permitted), quotas, my requests; approve/decline for managers
- [ ] Watchlist, blocklist (managers), issues

Done when: a title can be found, requested and followed to "available", then played, without leaving the app.

## M5: Adult extension (optional, removable)
- [ ] Extension modules (data, presentation, Compose UI, SwiftUI) plugged in through ADR 0008; builds without it keep working
- [ ] Access rules enforced in shared code: server switch, user permission, per-user safe mode, blurred artwork until revealed
- [ ] Catalogue and requests from a compatible Seerr server; playback from Stash with resume and play counts kept in Stash
- [ ] Decide how apps reach Stash. Stash has one admin key and copies it into every stream URL it returns, so other people's devices must
      not get it: a server-side gateway with per-user checks, and a direct key only for single-user setups
- Details are kept privately while the repo is public.

Done when: with the extension included, its catalogue can be browsed, requested and played under the access rules; without it, the app
behaves exactly as before.
