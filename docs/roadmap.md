# Roadmap

[x] done, [ ] not started. Each milestone is a vertical slice that ends with something usable; "Done when" is the exit check.
Agreed on 2026-10-18: Windows desktop and web first; the first usable version is a Jellyfin client (browse + play); anyone may use the
app, so services are optional (ADR 0008); the design is modular, with no extensions (ADR 0014). Reorder later milestones as priorities change.

## Principles
- Anyone may use Current against their own servers. Every service (Jellyfin, Seerr, Stash) is optional at runtime (ADR 0008). No
  extensions: modules talk through interfaces, so any component can be replaced (ADR 0014).
- All logic is shared Kotlin; SwiftUI and Compose only render state (ADR 0005, 0006). Playback UI is always our own (ADR 0007).
- Check API facts against the server's own spec before coding (docs/platform-notes.md). The repo is public: no hostnames, keys or
  private server details in code, docs or commits.

## M1: Foundations and Jellyfin sign-in (Windows desktop, web)
Spikes first: they decide whether the first slice works at all. Each ends in an ADR or a docs/platform-notes.md entry.
Compose Multiplatform has no supported way to draw Compose over native video on either platform, so every candidate is a workaround
(details and sources: docs/platform-notes.md).
- [x] Desktop video (2026-10-19, ADR 0010): libmpv in a native child window with a transparent Compose controls window and our own
      borderless fullscreen. The texture route works but is SDR only; vlcj not tried. Needs our own LGPL-2.1 libmpv/FFmpeg build (with
      Windows media controls)
- [x] Web UI (2026-10-19, ADR 0011): React + TypeScript (Vite) over the Kotlin core compiled to Kotlin/JS, chosen over Compose HTML and
      Compose for web after three prototypes and the owner's hand checks. Web playback is `<video>` + hls.js with a device profile built
      only from browser probes (direct play, server remux, server transcode); HDR10 HEVC plays in HDR on Chrome and Edge
- [x] Dependency licences: permissive and LGPL-2.1 only, no GPL in distributed builds (ADR 0009); two editions, Store and Private
      (ADR 0014)
- [x] Current's own code is proprietary: no open-source licence, no LICENSE file (ADR 0009)
- [x] Supported server versions: the latest releases only (Jellyfin 12.2 and Seerr 3.5.0 on 2026-10-18); follow new releases rather than
      keeping older ones working

Then:
- [x] Libraries per ADR 0002, versions checked against Kotlin/CMP: Ktor client, kotlinx.serialization, Koin, Navigation, Coil 3
      (2026-10-19; Navigation is 2.10.0-rc01, the line CMP 1.12.1 pairs with)
- [x] Capabilities state (2026-10-19, ADR 0014): what each configured server offers, read by features to hide what is unavailable.
      Extensions, extension points and the build switch dropped for a modular design with two editions
- [x] `core:model`: media identity (service + id), open media kinds, artwork with aspect ratio, user and permissions (2026-10-19,
      ADR 0013: the identity holds the server, not only the service; services are open like kinds)
- [x] `core:network` (2026-10-20, ADR 0015): one client per server that follows the server's current address, error model, lenient
      JSON, our own request log with tokens, keys and hosts redacted. Seerr's cookie session comes with Seerr sign-in (M3)
- [x] Server setup (2026-10-20, ADR 0016): add a Jellyfin server by URL, check it (public info endpoint, and that every address answers
      as the same server), warn about plain HTTP except on local addresses; saved in a per-platform key-value store. Logic and
      `ServerSetupViewModel` only: the screens come with the shells below
- [x] Several addresses per server (2026-10-20, ADR 0019), local (`http://192.168.1.10:8096`, `http://media.lan:8096`) and internet
      (`https://media.example.com`), in the user's priority order. The app picks the best one that answers and roams between them as the
      network changes (start, network change, failed request, and a periodic check to move back to local). Credentials go only to an
      address that proves to be the same server. Compose screens to list, add, remove and reorder them (Settings > Addresses)
- [x] Spike: find servers on the local network (2026-10-20, platform notes "Local server discovery, run on devices"): Jellyfin only
      (Seerr and Stash have no discovery); directed broadcast per interface on desktop and Android, unicast probes of typed addresses on
      iOS (broadcast needs Apple's multicast entitlement), nothing on the web; Android 17 needs `ACCESS_LOCAL_NETWORK` for any local
      request. macOS and tvOS still to run
- [x] Secure storage and device identity (2026-10-20, ADR 0017): Windows Credential Manager, the Secret Service on Linux (memory, or a
      file the user chooses, without one), `localStorage` on the web; one random device id per install in a machine-local store; the
      app version servers see. Android and Apple keep secrets in memory until M4
- [x] Jellyfin sign-in (2026-10-20, ADR 0018): username and password or Quick Connect with that device id, the server id checked
      against the saved one, sign out, sessions restored at start and dropped on a 401. Logic and ViewModels; the screens come with the
      shells below. Password and Quick Connect sign-in, restore and sign-out checked against a live server
- [x] Compose shell (desktop) (2026-10-20): theme from design tokens, navigation assembled from registered destinations, sidebar layout,
      settings (servers, sign out, about), loading/error/empty states, strings in resources; `HomeViewModel` for the first screen.
      Keyboard alone works throughout. Add, sign in (password, Quick Connect), restart signed in and sign out checked with the keyboard on
      Linux against a local stand-in for the sign-in endpoints; a real server on Windows is the owner's hand check. Android shows this desktop layout until its own layouts (M4)
- [x] Web shell (2026-10-21, ADR 0011):
  - [x] pure-Kotlin modules gain a `js()` target (they lose `wasmJs`, and the Compose modules leave the web);
  - [x] a Kotlin/JS umbrella module (`web`) with the `@JsExport` facade;
  - [x] the browser probes and web device profile in `core:playback`, tested against `docs/web-probes/`, with Dolby Vision probes;
  - [x] `webApp` becomes the Vite + React + TypeScript app, with the same sidebar layout, settings and states as desktop: home's
        states, settings (servers, sign in and out, remove, where sign-ins are kept, about), add server, sign in with a password or
        Quick Connect, keyboard use and Back over the browser's history, light and dark. Checked in Chrome against the real core and a
        local stand-in, and by the owner's hand against a live server (docs/platform-notes.md, "Web shell against the real core");
  - [x] routing through the core's History API router; npm in CI with a licence check
- [x] Opt-in live smoke tests (2026-10-20, `LiveJellyfinSmokeTest`): run only when `CURRENT_LIVE_*` environment variables are set, never
      in CI; read-only apart from a sign-in they end again. Password and Quick Connect sign-in, restore and sign-out passed against a live 12.2 server
- [x] Android network setup (2026-10-21, ADR 0020, PR 27): cleartext, `INTERNET` and the local network permission; Android polish
      (2026-10-21, PR 36): the local network ask on Home, first-Tab focus ring, APK check per module
- [x] Apple: device name without a network lookup, and the local network keys (2026-10-21, PR 34)
- [x] Full code review (2026-10-21, docs/reviews/2026-10) and its first fixes (2026-10-21, PRs 41-46): sign-in and session robustness,
      the request log with Copy diagnostics, local network rules, web hardening (CSP), Compose navigation and backup rules, the desktop
      MSI (per-user, installed, upgraded and launched on Windows)

Done when: sign in and out of Jellyfin on Windows and in the browser, and the app restarts signed in.
State (2026-10-21): met in the browser against a live server. On Windows only against a local stand-in so far; a run against a real
server is the owner's hand check.

## M2: First usable version: Jellyfin browse and play (Windows desktop, web)
- [ ] `data:jellyfin`: libraries, items (paging, sort, filter), latest, resume, next up, series/seasons/episodes, details, similar,
      search, images (+ blurhash), played/unplayed, favorites
- [ ] Home: Continue Watching, Next Up, Latest per library; users can reorder, hide and add sections
- [ ] Library grids, detail screens (movie, series, season, episode), search; home videos, playlists, collections, extras (behind the
      scenes, deleted scenes, interviews), multiple versions and parts; directors and other crew shown and searchable
- [ ] `core:playback`: `PlayerEngine`, `EngineCapabilities`, `PlaybackPlanner` (Jellyfin playback info + device profile from the
      engine's capabilities: direct play, direct stream, remux or HLS transcode)
- [ ] `feature:player`: `PlayerController` (resume, progress reporting with pings while paused, audio/subtitle tracks, quality limit,
      next episode, skip intro/credits where the server has a media-segment plugin, fall back to transcode on engine errors)
- [ ] Engines: desktop (from the spike, ADR 0010: our LGPL-2.1 libmpv/FFmpeg build, JVM binding, window host and its follow-ups),
      web (HTML video + hls.js)
- [ ] Player UI in Compose (desktop) and React (web): transport, seek bar with chapters, track and quality menus, fullscreen, keyboard
      shortcuts, auto-hide
- [ ] Web player follow-ups (ADR 0011):
  - ask for a new route when the display's dynamic range changes;
  - check HDR on screen by eye;
  - render ASS in the browser instead of burning it in (a JavaScript renderer; check its licence first)
- [ ] Media keys: Windows (System Media Transport Controls, in our libmpv build per ADR 0010), Media Session API on web
- [ ] The rest of the player feature target (ADR 0007) as far as Windows and web allow: HDR output, subtitle appearance, delay and preferred
      languages, remembered quality and zoom, a playback info overlay, a problem report with redacted logs
- [ ] Deploy the web build (static files) behind a reverse proxy for daily use

Done when: a Jellyfin library is browsable and playable on Windows and web every day, with resume and progress synced to the server.

## M3: Seerr: discover and request

- [ ] Discover rows as the server configures them, Movies/Series browse with filters, search merged with library results
- [ ] Movie, series, person and collection pages joined with Jellyfin through Seerr's media records first, provider ids second (often missing)
- [ ] Requests: request (seasons, 4K, advanced options when permitted), quotas, my requests; approve/decline for managers; request

## M5: Adult content
- [ ] Its modules (data, presentation, Compose UI, SwiftUI) like any other feature; hidden unless a server offers it and the user may see it
- [ ] Access rules enforced in shared code: server switch, user permission, per-user safe mode, blurred artwork until revealed
- [ ] Catalogue and requests from a compatible Seerr server; playback from Stash with resume and play counts kept in Stash
- [ ] Decide how apps reach Stash. Stash has one admin key and copies it into every stream URL it returns, so other people's devices must
      not get it: a server-side gateway with per-user checks, and a direct key only for single-user setups
- Details are kept privately while the repo is public.

Done when: its catalogue can be browsed, requested and played under the access rules; without a server that offers it, the app
behaves exactly as before.
